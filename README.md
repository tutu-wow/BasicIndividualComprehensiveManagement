# 个人综合管理小程序

> ECharts 数据看板 · 健康数据记录与趋势查看 · 目标拆解与进度管理 · 日程待办与番茄钟 · 习惯打卡 · 收支统计 · 个人生活记录 · 跨模块智能提醒

身边同学管生活基本靠一堆 App：记步数一个、记账一个、待办一个、打卡又一个，装到最后数据东一块西一块，谁也不认识谁。可这些事本来就连在一起——步数连续几天掉下去，本该有人提醒你动一动；待办拖过期了，本该有人催你一下；月底花超了，本该有人给你提个醒。

这套系统就顺着"把个人数据放到一处管"的思路做：健康、目标、日程待办、习惯打卡、番茄钟、收支和生活记录集中在一个人端，再配上数据看板和跨模块联动提醒，让记录不只是躺在列表里。对做毕设的同学来说，"数据怎么跨模块联动起来"这条线，比单纯堆增删改查有讲头得多。

---

## 一、项目简介

个人综合管理系统采用前后端分离架构，由面向普通用户的 uni-app 微信小程序、面向管理员的 Web 管理端和 Spring Boot 服务端组成。系统围绕个人健康、目标、时间、收支及生活记录等日常管理场景，将健康记录、目标任务、日程待办、习惯打卡、番茄钟、收支、物品、备忘录和日记等数据集中管理。普通用户可在小程序端完成个人数据维护、统计查看和提醒消息查阅；管理员可在管理端维护用户、健康标准、收支分类、习惯模板、联动规则、公告与反馈，并查看平台运营和使用情况。

## 五、核心实现说明

### 5.1 用户账号、角色与登录状态

系统区分普通用户与管理员两类角色。普通用户在小程序端完成注册、账号密码登录、密码找回或修改、个人资料维护以及微信绑定等操作；管理员通过 Web 管理端登录，进入用户管理、业务数据维护和统计分析页面。登录成功后，服务端生成 JWT，前端将认证信息保存到本地状态与缓存中，后续请求在请求头中携带 Bearer Token；服务端拦截器解析令牌中的用户标识和角色信息并写入当前请求上下文，为不同端的菜单跳转、个人数据查询和业务数据归属提供依据。

```
用户注册或登录 → 获取并保存 JWT → 请求接口时携带认证信息 → 服务端解析当前用户与角色 → 进入小程序个人管理功能或管理端业务功能
```

### 5.2 健康记录、标准配置与趋势查看

健康模块以每日健康记录为核心，用户可维护步数、睡眠时长与质量、饮食内容及图片、体重、饮水量等信息，并按时间查看历史数据。健康中心将个人记录与健康标准对照展示，用户可从页面进入新增记录和趋势查看入口；趋势页面围绕步数、睡眠、体重和饮水量等维度呈现数据变化。管理端可查看全体用户的健康记录，按用户或日期筛选相关数据，并维护步数目标、推荐睡眠时长等健康标准，为前端的健康达成提示和平台健康数据分析提供配置基础。

| 功能入口 | 主要数据与处理方式 |
| :--- | :--- |
| 健康记录 | 以用户和记录日期归档步数、睡眠、饮食、体重、饮水量等信息，支持新增、编辑、查询和删除 |
| 健康趋势 | 按记录时间汇总个人健康数据，在趋势页面查看不同指标的变化情况 |
| 健康标准 | 管理员统一维护健康达成参考值，用户端据此展示个人记录与标准的对照信息 |

### 5.3 目标规划、任务拆解与进度联动

用户可创建长期或阶段性目标，维护目标名称、说明、截止日期、优先级、进度和状态，并在目标中心按状态浏览目标。每个目标可继续拆分为多个子任务，用户在任务列表中新增、完成或删除任务；目标详情页展示任务清单及已保存的目标进度。任务完成状态可独立切换，首页和目标中心则读取目标的进度字段呈现当前完成情况。对于有明确时间安排的任务，系统还提供将目标任务加入日程的入口，使目标拆解与日常安排形成关联。

```
创建目标并维护进度 → 新增与管理子任务 → 切换任务完成状态 → 在首页和目标中心查看目标进度 → 可将任务加入日程继续执行
```

### 5.4 日程、待办、番茄钟与习惯打卡

时间管理模块将日程安排、待办执行、专注计时和习惯培养集中在个人生活中心。用户可创建包含开始结束时间、地点、提醒时间和分类的日程，并在日历视图中按日期查看安排；待办事项支持按全部、未完成和已完成状态筛选，维护优先级和截止时间，并可快速切换完成状态。番茄钟提供专注时长、休息时长和任务标签的设置，以及开始、暂停、重置和完成记录功能。习惯模块用于维护个人习惯并进行每日打卡，页面展示连续打卡、累计打卡和最长连续等信息。服务端同时提供目标进度、日程分类分布、每日专注趋势、番茄钟分布和每日完成情况等统计接口，供首页和时间统计页汇总个人时间投入。

| 时间管理模块 | 主要能力 |
| :--- | :--- |
| 日程与日历 | 维护日程信息并在日历中标记有安排的日期，支持关联目标任务 |
| 待办事项 | 按完成状态、优先级和截止时间组织个人待办，支持完成状态切换 |
| 番茄钟 | 按专注和休息时长进行倒计时，完成后保存专注记录 |
| 习惯打卡 | 维护习惯项目并记录每日打卡状态，统计连续天数和累计次数 |

### 5.5 收支管理与个人生活记录

收支模块支持记录收入和支出方向、金额、分类、日期、备注、交易单号及对方账户等信息。收支列表按照时间展示个人记录，统计页可按日、周、月切换查看收入、支出和结余，并对不同收支分类进行汇总，展示趋势与占比。管理员可维护全局收支分类，为用户录入数据时的分类选择提供统一来源。除收支之外，生活管理还提供个人物品清单、借还记录、备忘录和日记功能：物品可记录存放位置和状态，借还记录跟踪借出与归还情况，备忘录支持置顶管理，日记支持文字及图片记录，从而覆盖常见的个人生活信息沉淀需求。

```
录入收支记录 → 关联收支分类 → 按日期和方向聚合数据 → 计算收入、支出与结余 → 展示趋势和分类占比 → 为月度支出提醒提供数据来源
```

### 5.6 跨模块联动规则与智能提醒

系统通过联动规则把健康、待办、习惯和收支等模块连接起来。管理员可在管理端维护规则的触发条件、阈值、持续天数、提醒内容和启用状态，并查看规则执行日志。服务端启用定时任务，周期性读取已启用的规则并遍历普通用户数据：当前实现覆盖连续步数不足、连续睡眠不足、待办逾期、习惯断签和月度支出超阈值等情形。规则命中后会写入用户提醒消息，同时记录执行结果；同一规则对同一用户在当天只会执行一次，以避免重复提醒。用户可在小程序首页和提醒消息页面查看相关通知。

```
管理员维护并启用规则 → 定时任务读取用户健康、待办、习惯和收支数据 → 判断规则条件 → 写入提醒消息与执行日志 → 用户在小程序查看提醒
```

### 5.7 公告、意见反馈与后台运营维护

系统公告由管理员在 Web 管理端统一发布和维护，小程序端提供公告列表入口，便于用户获取平台通知。用户可在小程序提交意见反馈并查看处理结果；管理员在反馈管理页面集中查看反馈内容、回复信息和处理状态，形成"用户提交—后台处理—用户查看回复"的完整链路。管理端还提供用户账号管理、个人资料维护、密码修改和操作日志查询等通用管理能力，并可维护习惯模板、收支分类和健康标准等基础数据，为普通用户端的表单选择和日常操作提供统一配置。

### 5.8 多角色协作与数据分析

普通用户端负责个人健康、目标、时间和生活数据的录入、查询及统计查看；管理端负责平台数据维护、规则配置和运营观察。管理端首页与数据分析页面结合 ECharts 呈现统计结果，覆盖用户活跃度、模块使用情况和健康数据等维度；首页数据看板汇总用户、健康记录、目标、日程等核心业务数量。用户端首页则汇总待办完成情况、当月收支、目标进度、日程安排和健康概览，使分散在不同模块中的个人数据能够在同一页面快速浏览。

| 分析模块 | 主要数据关注点 |
| :--- | :--- |
| 用户活跃度 | 用户注册及活跃趋势等平台用户数据 |
| 模块使用统计 | 健康、目标、日程、待办、习惯、收支等功能的使用情况与排行 |
| 健康数据统计 | 平台健康记录的步数、睡眠、体重等数据汇总与分布 |
| 个人数据总览 | 个人待办、目标、日程、收支和健康信息的首页概览与时间统计 |

### 5.9 前后端分离与统一服务支撑

服务端采用 Controller、Service、Mapper、Entity、DTO 等分层组织方式，将用户、健康、目标、任务、日程、待办、习惯、收支、生活记录、规则提醒和后台分析拆分为独立业务接口。普通结果和分页结果采用统一的数据结构返回，前端通过封装后的请求方法调用接口；服务端使用 MyBatis-Plus 进行数据访问，并由 MySQL 持久化业务记录。小程序端使用 Pinia 管理登录态和用户信息，Web 管理端通过路由守卫和角色信息控制后台页面访问，二者复用同一套服务接口和数据模型，从而保证个人端操作、后台维护和数据统计之间的数据连贯性。

## 八、适合谁

- 想做**选题贴近生活**的毕设：健康、目标、时间、收支一站管理，选题动机一句话讲得清

- 想体现**多角色协同**能力的同学：用户端负责记录与执行，管理端负责基础数据、规则配置与运营观察
- 需要**数据可视化落点**的场景：ECharts 环形图、进度条、趋势与占比图，论文有图有数据
- 想练**前后端分离**的同学：Controller／Service／Mapper 分层 + MyBatis-Plus + JWT，接口设计与鉴权链路清晰
